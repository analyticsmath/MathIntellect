## 1. What the studio must demonstrate

Valtum Studio's brief positions the work as evidence of software engineering, product understanding and visual authorship for substantial international projects. Math Intellect must demonstrate all three simultaneously. A spectacular transition into a false result damages that positioning. A truthful result buried in an animated report also fails it.

The visitor should leave with three concrete understandings: assumptions can be changed; multiple outcomes can be inspected; a specified computation can be repeated. Photography supplies curiosity and physical consequence. The actual model supplies evidence. The visual system makes their relationship legible.

The film's protagonist is the visitor's **one scenario**, with a continuous origin, input snapshot and selected result. The splash series is its photographic world. It is not a fluid simulation or a verified sequence of exposures from one event.

## 4. What to learn from Personality Assessor's actual source

Reviewed files: `PublicMotionRoot.jsx`, `HomeSceneRenderer.js`, `PublicRouteTransition.jsx` in `analyticsmath/PersonalityAnalysis/frontend/src/components/public-experience/`.

Keep the single scroll owner, native touch mode, explicit source/destination actor identity and a frame function driven by normalized scroll progress. Preserve the original state when a visitor reverses or navigates back.

Do not copy these current implementation weaknesses:

1. `PublicRouteTransition` carries a background rectangle, with no actual photograph in its rendered carry element. A snapshot alone is not photographic continuity. Math Intellect's carry actor must contain the same media, crop and aspect ratio as the source.
2. Its destination query takes the first `[data-transition-actor]`; Math Intellect must match the selected actor ID so a different model cannot receive the image.
3. `HomeSceneRenderer` writes width and height on each scroll frame and retains a cached target rectangle. Prefer transform-based motion and invalidate layout measurements on resize/font/media changes. Measure layout separately from per-frame writes.
4. Pixel transition progress is put into React state every animation frame. Math Intellect needs no decorative pixel transition, and its continuous film should not rerender the component tree on every scroll tick.

Math Intellect's `MarketingShell` currently mounts `marketing/motion/DesktopLenisBridge.tsx`. A separate bridge exists under `marketing/components/` but is not mounted by this shell. The mounted version checks capabilities only at initialization. Later implementation must use one bridge that responds to viewport/pointer/reduced-motion changes, clears inertia on navigation, and scopes scene cleanup to the route. Do not mount both.

## 5. The tightened story

**Opening:** What if one thing changed?

**Inspection:** An outcome is only part of the story.

**Possibility:** One start. Many possible outcomes.

**Agency:** Change the condition.

**Comparison:** See what moved.

**Breadth:** Different questions. Different mathematics.

**Reproducibility:** Same inputs. Same result.

**Resolution:** Make the unknown something you can work with.

The visitor-facing film uses these short lines, one at a time. Shot numbers, scene IDs and engineering labels belong to this contract, never to the finished public page. Body copy explains only the decision currently available. Technical detail lives in Method and Workbench.
